# mikomai-cli chat 実行・仕様ガイド

`mikomai-cli chat` は、Mikomai デスクトップアプリケーションのチャット画面と**全く同一のバックエンドパイプライン（LLM、SurrealDB RAG、登録機器情報、MCP ツール実行エンジン）**を、ヘッドレス（CLI）から直接実行できるコマンドです。

GUI を起動することなく、端末上から自然言語でネットワークの質問をしたり、管理対象機器の自律診断を実行したり、シェルスクリプトや CI/CD ワークフローに組み込むことが可能です。

---

## 1. 基本的な使い方

### 実行構文

```bash
# npm スクリプト経由（推奨）
npm run cli -- chat "<メッセージ>" [OPTIONS]

# Cargo 経由（プロジェクトルートから）
cargo run --manifest-path src-tauri/Cargo.toml --bin mikomai-cli -- chat "<メッセージ>" [OPTIONS]
```

### オプション

| オプション | 説明 |
| --- | --- |
| `--json` | 出力を機械可読な JSON 形式（`{"ok": true, "data": {"response": "..."}}`）で出力します。 |
| `-d`, `--debug` | AgentLoop やモデル読み込み等のデバッグ・内部動作ログを標準エラー出力に表示します（エイリアス: `--verbose`）。デフォルトは無効（内部出力なし）で、最終回答のみが出力されます。 |
| `-h`, `--help` | ヘルプメッセージを表示します。 |

## 2. 実行モードの自動ディスパッチ

`chat` コマンドに渡されたメッセージは、内部の `harness::dispatch::select_dispatch_mode_for_request` によって解析され、タスクの性質に応じて **Worker モード** または **Agent モード** に自動的に振り分けられます。

```text
ユーザーメッセージ (CLI)
        │
        ▼
select_dispatch_mode_for_request
   ├── [設定解説・技術ドキュメント質問] ───► DispatchMode::Worker (高速・単発回答)
   │                                            │
   │                                            ├─ SurrealDB RAG 検索
   │                                            └─ LLM 回答生成
   │
   └── [実機の状態確認・調査依頼]       ───► DispatchMode::Agent (自律ループ)
                                                │
                                                ├─ AgentLoop (最大10ステップ)
                                                ├─ 安全ポリシー検査 (Read-Only ガード)
                                                ├─ MCP ツール実行 (get-state, arp, routes等)
                                                └─ 総合診断レポート生成
```

### モード 1: Worker モード（単発ナレッジ回答）
- **対象**: ネットワーク仕様の解説、コマンド構文の作成、一般的なトラブルシューティング手順の相談など、機器への直接アクセスを伴わないリクエスト。
- **動作**: RAG（SurrealDB にインジェストされたドキュメント）を必要に応じて参照し、Router / Knowledge Worker が LLM を用いて直接回答テキストを生成します。

### モード 2: Agent モード（自律型エージェントループ）
- **対象**: 登録済み機器のホスト名や IP アドレスが含まれるリクエスト（例: `NakaokuGW のインターフェース状態を調べて`）。
- **動作**: `AgentLoop` が起動し、目標達成に必要な観測（ARP テーブル取得、ルーティング確認など）を自律的に判断して MCP ツールを実行します。得られた観測結果（Observation）を統合して最終的な診断結果を出力します。
- **安全性**: 観測操作は厳格なポリシーバリデータにより検証され、未承認の設定変更や副作用を伴う操作は遮断されます。

## 3. 実行例

### 例 1: 設定コマンドの生成・技術仕様の質問（Worker モード）

```bash
npm run cli -- chat "YAMAHA RTX1210 で LAN1 インターフェースに IP 192.168.10.1/24 を設定するコンフィグを作成して"
```

**出力例**:
```markdown
YAMAHA RTX1210 で LAN1 インターフェースに IP アドレス `192.168.10.1/24` を設定するコマンドは以下の通りです。

```text
# 管理者モードに移行
administrator

# LAN1 インターフェースの IP アドレス設定
ip lan1 address 192.168.10.1/24

# 設定の保存
save
```
...
```

### 例 2: 登録機器の状態確認と自律診断（Agent モード）

登録機器のホスト名（例: `NakaokuGW`）を指定して診断を依頼します。

```bash
npm run cli -- chat "NakaokuGW のインターフェースとルーティングテーブルを確認して、デフォルトルートが存在するか教えて"
```

**内部動作**:
1. ディスパッチャが `Agent` モードを選択
2. `AgentLoop` が `NakaokuGW` に対する `interfaces` および `routes` の取得ツールを呼び出し
3. 取得した生データを解析し、デフォルトゲートウェイ（`0.0.0.0/0` や `default`）の有無を特定
4. 自然言語で結果をまとめて端末に出力

### 例 3: JSON 出力による外部連携（CI / スクリプト）

`--json` を指定すると、標準出力に構造化 JSON が出力されます。

```bash
npm run cli -- --json chat "FITELnet F220 の VLAN 設定の注意点を箇条書きで3点教えて"
```

**出力例**:
```json
{
  "ok": true,
  "data": {
    "response": "FITELnet F220 での VLAN 設定における主な注意点は以下の 3 点です：\n1. ...\n2. ...\n3. ..."
  }
}
```

## 4. デスクトップアプリとのデータ共有

`mikomai-cli chat` は、Tauri アプリケーションのランタイムコンテキストを共有して実行されるため、デスクトップアプリで設定した以下のデータがそのまま利用されます。

| データ種別 | 格納場所 / 参照元 | 説明 |
| --- | --- | --- |
| **LLM 設定** | `settings.json` | 使用する LLM プロバイダ（ローカル GGUF / OpenAI / Claude / Ollama）、API キー、温度パラメータ、履歴制限など |
| **登録機器情報** | `connections.json` | 接続対象機器のホスト名、IP アドレス、接続プロトコル（SSH / Console / Telnet） |
| **ナレッジベース** | SurrealDB (RocksDB) | `rag-ingest` で取り込まれたネットワーク技術ドキュメントのベクトルインデックス |
| **会話履歴サマリー** | `history` ストア | 過去のセッションの要約情報（コンテキスト長の上限に応じて参照） |

## 5. 自動化スクリプトでの活用例

### ネットワーク簡易監視・障害調査スクリプト

`jq` と組み合わせて、定期実行シェルスクリプトから AI に機器状態を診断させることができます。

```bash
#!/usr/bin/env bash
set -euo pipefail

TARGET_DEVICE="NakaokuGW"
PROMPT="${TARGET_DEVICE} の ARP テーブルとインターフェース状態を確認し、リンクダウンしているポートや異常がないか報告してください。"

echo "Checking network status via mikomai-cli..."
RESULT=$(npm run cli -- --json chat "$PROMPT" | jq -r '.data.response')

echo "----------------------------------------"
echo "$RESULT"
echo "----------------------------------------"
```

## 6. 注意点とトラブルシューティング

### 1. LLM 設定のエラー（モデル未設定・APIキー未設定）
- **事象**: `chat` 実行時に LLM の呼び出しでエラーが発生する。
- **対処**: 初回はデスクトップ GUI アプリを起動し、設定画面（Settings）で使用する LLM モデル（ローカル llama.cpp モデルのパス、または外部 API のエンドポイントとキー）が正しく設定されているか確認してください。

### 2. SurrealDB のロック競合
- **事象**: `Database locked` や接続タイムアウトが発生する。
- **原因**: 組み込み RocksDB は単一プロセスによる排他アクセスを前提としています。GUI アプリが起動している最中に CLI を実行するとロック競合が発生する場合があります。
- **対処**: 大規模な検索やナレッジ更新を行う場合は、GUI アプリを終了してから CLI を実行してください。

### 3. 初回実行時の遅延
- ローカル GGUF モデル（llama.cpp）を使用している場合、初回実行時にメモリへのモデル展開が行われるため、数十秒程度のウォームアップ時間がかかることがあります。
